# 海外综合看板更新全流程

## 0. 确定输入输出
常见输入：一份当期 `*.xlsx` 模板以及上一版 `海外综合看板-*.html`。输出：日期化的新版独立 HTML、数据校验结果、变更日志；需要时再提供跨期对比报告。

检查用户是否只要求**更新数据**、同时修改模块，还是仅做 1109/1116 等历史对比。只有“更新模板”时默认保留布局、筛选、业务口径。

## 1. 备份与追溯
- 不直接覆盖旧文件。
- 保存：Excel 文件名、导出日期、表名、HTML 基准版本、操作者、更新日期。
- 标注数据来源是本期原始 Excel，不是旧 HTML 的历史快照。
- 将当前工作簿、看板、对比报告原件留在受控存储，而不是公开仓库。

## 2. Excel 结构核对
历史 1116 模板包含：`新品N3 MAX` 工作表（A1:S10），`EOL` 工作表（A1:W70）；**每期重新验证实际范围**。

历史行列口径：第 1-2 行分组表头，第 3 行汇总，第 4 行真实列标签，第 5 行起为产品/国家明细。不要把第 3 行汇总再次累加。

| 列 | 说明 | 数据属性 |
| --- | --- | --- |
| A-D | 产品大类、型号、国家、匹配键 | 维度 |
| E-G | 8、9、10 月实际销量 | 数值 |
| H | 11 月实际销量 | 数值 |
| I | 8–10 月均销量 | 数值，可含小数 |
| J | 11 月 FCST | 数值 |
| K | FBA（含 FBA 在途） | 库存 |
| L | 海外仓（含海外仓在途） | 库存 |
| M | 未生产订单 | 库存口径构成 |
| N | 国内仓 | 库存 |
| O | 在途总（仅展示） | **不能再次加总** |
| P | 总计（不含售后仓） | 模板源值 |
| Q | 不可售 | 模板源值 |
| R | 单价 | 金额辅助 |
| S | 库存金额（含未生产） | 模板源值 |
| T-U | 售后仓全新 / 二手 | 仅 EOL |
| V | 售后仓翻新库存金额 | 仅 EOL |
| W | 售后仓待翻新 | 仅 EOL |

缺列、重名列、单位变化、月份滚动时先核对，不沿用过期列索引。额外字段需先核对用户新模板。

## 3. 数据建模
内部数据分层：
- `N3_COUNTRY`：每个国家/型号一行，允许同一国家有 Bundle 等多个型号。
- `N3_SUMMARY`：全量 N3 数值汇总。
- `EOL_COUNTRY`：SKU / 型号 / 国家明细。
- `EOL`：按产品大类聚合，用于 SKU 分组和 TOP8。
- `EOL_SUMMARY`：整体 EOL 汇总。
- `meta`：数据导出日期、同步日期、来源文件、产品数和覆盖地区数。

前端需要的典型字段：`major,model,country,m7,m8,m9,m10,avg710,fcst10,fba,wh,unproduced,dom,transit,total,unsellable,cost,refurb_new,refurb_used,refurb_pending,refurb_cost,total_after`。

使用 `node scripts/validate-snapshot.mjs ...` 校验 JSON。此脚本仅做结构和基础口径检查，无法取代与 Excel 核对。

## 4. 更新 HTML
1. 使用上版 HTML 作为基础，锁定现有 CSS、导航、表格、筛选与排序。
2. 生成本期 `DATA` 对象并写入；提供了 `scripts/update-dashboard.mjs` 进行结构化替换。
3. 用当前模板的日期和文件名替换页面中**静态的旧数据来源文本**，并更新 `meta`。
4. 检查代码里存在的历史说明是否已过时，尤其“德国 9 月放量明显”等本期不一定适用的陈述。
5. 文件另存为日期化版本，不覆盖历史。

## 5. 校验并交付
- Excel 行数、国家数、SKU 数；明细汇总 vs 汇总行。
- N3 实际/FCST、库存金额、不可售；EOL TOP8、周转天数、售后仓和总库存。
- 浏览器交互：切换 N3/EOL、筛选 SKU/国家、重置、排序、固定列、横向滚动。
- JS 控制台无错误；移动端布局不溢出。
- 交付时列出：源文件、基准版本、快照日期、修改范围、通过与未通过的检查。

## 6. 归档与发布原则
公开 GitHub：只提交操作说明、校验程序、脱敏演示数据和演示 HTML。真实经营数据应进入批准的**私有**仓库或企业系统。对于不可读取的历史文件，维护清单即可，不用猜测补全。
